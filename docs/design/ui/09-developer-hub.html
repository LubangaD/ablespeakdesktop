uia_act

Screen Try in Test console

Description

Act on a control in the front window through Windows UI Automation, using the pattern the control itself supports — Invoke, Value, Scroll, ExpandCollapse or SelectionItem. Does not move the mouse, so it cannot miss, and costs nothing per call.

Parameters

target required
The control’s name or automation id, as read_screen reported it
pattern required
One of Invoke, Value, Scroll, ExpandCollapse, SelectionItem
value
The text to set, for the Value pattern

Function schema

{
  "name": "uia_act",
  "description": "Act on a control in the front window through its own UI Automation pattern.",
  "parameters": {
    "type": "object",
    "properties": {
      "target":  { "type": "string", "description": "Name or automation id" },
      "pattern": { "type": "string",
                   "enum": ["Invoke","Value","Scroll","ExpandCollapse","SelectionItem"] },
      "value":   { "type": "string", "description": "For the Value pattern" }
    },
    "required": ["target", "pattern"]
  }
}

Prompt — /developer/prompt

This is sample text, not the live prompt. The server writes the real prompt for every request (ai-engine.js, _buildSystemPrompt) and does not share it with the dashboard. These outlines describe what it is told in each mode.

Command mode

Outline · not the live text 
You control a Windows computer for someone who cannot use a
keyboard or mouse. You are given the front window's controls,
read through Windows accessibility.

· Act through the named control, never a guessed coordinate.
· Ask before anything that cannot be undone: deleting,
  sending, submitting, closing unsaved work.
· Say what you did in plain words. Never read out a web
  address — say what is opening.
· If you cannot do it, say so and say what to try.

About this text

Kept in the dashboard so a developer can read what each mode is for. To see what was actually sent, use the Logs tab.
